My AFRP — Portal Screens

A mobile-first redesign of every module of the existing my.afrp.org member portal — the Power Pages / Dynamics 365 site currently in production — presented as sixteen annotated screens. This is the screen-level companion to the My AFRP Portal Build Spec: every colour, size, and component on this page comes from that document's :root tokens and .c-* classes, copied verbatim. Nothing here is a new platform. It is the same portal, the same modules, the same Authorize.Net payment stack — laid out so it works on a phone.

How to read these screens

Each frame is a real 375 px-wide rendering, not a drawing — the markup inside every phone is the markup a developer should ship, using only the classes defined in the build spec. Resize this page and the screens reflow exactly as the portal will.

Build notes

What is reused, not invented

Everything inside the phone frames uses the build spec's classes unchanged: .c-btn, .c-input, .c-field, .c-card, .c-tiles, .c-tile, .c-row, .c-dl, .c-pill, .c-alert, .c-switch, .c-choice, .c-actionbar. The only additions are the device frames and annotation chrome on this page, plus three small in-screen helpers (.seg, .amt, .av) built entirely from the same tokens. One correction runs the other way: the spec's .c-btn--sm is 40 px, which falls below the 44 px WCAG 2.2 floor as soon as it carries a real action, so it is 48 px inside these screens. Fold that back into §4.1.

One system, two documents If a value on this page differs from the build spec, the build spec wins and this page is wrong.
